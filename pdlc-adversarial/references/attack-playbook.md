# Team Black 공격 플레이북 (Attack Surface Catalog)

목표: 명세가 다루지 않은 틈으로 실제 버그·에러·권한 이탈을 유발한다. 스택은 Next.js App Router + Supabase + zod 고정. 각 표면마다 "어디를 노리나 / 어떻게 / 성공 판정 기준"을 정의한다. **6단계 QA가 이미 커버한 케이스 재현은 성공으로 치지 않는다.**

## 1. 입력 경계·오염 (Input boundary & malformed data)
- 필드 최대 길이 초과, 음수·0·소수, 빈 문자열, 유니코드/이모지/제어문자, 아주 긴 페이로드
- zod 스키마를 우회하는 경로: 서버 액션이 아닌 API 라우트, 검증 전에 쓰이는 `formData.get()`
- 성공 판정: 500 에러, 잘못된 데이터 저장, 검증 메시지 없이 통과

## 2. 인증·인가·RLS 우회 (AuthZ / RLS bypass)
- 타 사용자 소유 레코드의 ID를 직접 지정해 조회·수정·삭제 시도 (IDOR)
- 클라이언트가 넘긴 user_id를 서버가 그대로 신뢰하는지
- 로그아웃/만료 세션으로 mutation 호출, 권한 없는 역할로 관리 기능 접근
- 성공 판정: 권한 밖 데이터 접근·변경 성공, RLS 정책 누락 노출

## 3. 동시성·중복 (Concurrency & duplication)
- 같은 요청 빠르게 2회(더블 클릭, 재시도): 중복 생성, 재고/한도 이중 차감
- 두 사용자가 같은 자원을 동시에 수정 (경합, lost update)
- 결제·재고·쿠폰 등 "수량이 있는" 자원에 집중
- 성공 판정: 중복 레코드, 한도 초과, 음수 재고

## 4. 상태 전이 파괴 (Broken state transitions)
- 순서를 건너뛴 호출: 결제 전 배송 확정, 취소된 주문 재취소, 이미 사용한 쿠폰 재사용
- 뒤로가기/새로고침 후 만료된 폼 재제출
- 성공 판정: 명세상 불가능한 상태 조합 도달

## 5. 자원 고갈·성능 (Resource exhaustion)
- 대량 목록 요청(페이지네이션 없는 엔드포인트), 무거운 쿼리 반복
- N+1 유발 경로, 인덱스 없는 컬럼 정렬/필터
- 성공 판정: 응답 급격 지연, 타임아웃, DB 부하

## 6. 주입 (Injection)
- SQL(파라미터화 우회 시도), XSS(사용자 입력이 이스케이프 없이 렌더되는지), 파일 업로드 시 확장자·MIME 위장
- 성공 판정: 스크립트 실행, 쿼리 변조, 위험 파일 저장

## 7. 클라이언트 신뢰 값 (Client-trusted values)
- 가격·할인율·권한 플래그·합계가 클라이언트에서 계산되어 서버가 검증 없이 받는지
- 숨겨진 폼 필드·요청 바디 조작
- 성공 판정: 조작된 값이 서버에 반영 (예: 가격 0원 주문 성립)

## 8. 오류 경로 악용 (Error-path abuse)
- 의도적으로 에러를 유발해 노출되는 스택 트레이스·DB 에러·내부 경로 수집
- 부분 실패 시 롤백 누락으로 데이터 정합성 깨기
- 성공 판정: 민감 정보 노출, 정합성 붕괴

## 라운드 2 집중 지점
1라운드에서 Team White가 진단한 RISK 클래스를 우선 공략한다. 수정이 새 이음새를 만드는 경우가 많다 — "이 곳을 고쳤으니 같은 패턴의 다른 곳은?"이 2라운드의 기본 질문이다.

## 공격 강도 원칙
선의의 전력(good-faith best effort). Team White가 치울 것을 알기에 봐주는 순간 이 스킬은 무의미해진다. 단, 이 프로젝트 밖의 시스템·계정·외부 서비스는 공격 대상이 아니다.
