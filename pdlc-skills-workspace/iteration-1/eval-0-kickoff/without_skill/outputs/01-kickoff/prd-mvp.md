# PRD — RunMate MVP (러닝 크루 매칭)

- **버전**: v1.0 (2026-07-02 킥오프 확정)
- **범위**: 6주 MVP. 이 문서에 없는 기능은 만들지 않는다.

---

## 1. 페르소나

### 페르소나 A — "입문 러너 지수" (핵심 타깃)
- 29세, 판교 직장인. 러닝 시작 3개월 차, 페이스 7'00"/km.
- **니즈**: 혼자 뛰면 금방 그만둠. 같이 뛸 사람이 필요한데, 잘 뛰는 크루에 끼면 민폐일까 봐 걱정.
- **핵심 시나리오**: "우리 동네에서, 평일 저녁에, 나랑 비슷한 페이스로 뛰는 초보 환영 크루"를 찾고 싶다.

### 페르소나 B — "크루장 민혁" (공급자)
- 34세, 5년 차 러너. 한강 크루 운영 중.
- **니즈**: 인스타 DM으로 오는 가입 문의를 매번 수동 응대. 페이스 안 맞는 지원자를 거르는 게 힘들다.
- **핵심 시나리오**: 크루 조건(지역/요일/페이스 밴드)을 명시해 두고, 조건 맞는 지원만 받아 승인하고 싶다.

## 2. 핵심 유저 플로우

```
[러너]  가입 → 프로필 작성(지역·페이스·시간대) → 크루 탐색(필터/추천)
        → 크루 상세 확인 → 가입 신청 → (승인 대기) → 승인됨
        → 크루 세션 일정 확인 → 참석/불참 응답

[크루장] 가입 → 프로필 작성 → 크루 개설 → 가입 신청 알림 확인
        → 지원자 프로필 검토 → 승인/거절 → 세션 일정 등록 → 참석자 확인
```

## 3. 기능 명세

### F1. 인증 (P0)
- 이메일+비밀번호 가입/로그인/로그아웃. (여유 시 카카오 로그인 1종 추가 — P2)
- 비로그인 상태: 크루 탐색/상세는 열람 가능, 신청·개설은 로그인 요구.
- **완료 조건**: 세션 유지, 보호 라우트 리다이렉트, 기본 유효성 검사.

### F2. 러너 프로필 (P0)
- 필드: 닉네임, 프로필 이미지(선택), 활동 지역(시/구, 복수 1~3개), 평균 페이스(분'초"/km 슬라이더), 선호 요일(복수), 선호 시간대(아침/점심/저녁/심야), 러닝 목적(다이어트/기록 단축/친목/대회 준비), 자기소개(선택).
- 가입 직후 프로필 작성 온보딩 스텝 강제 (미작성 시 신청 불가).
- **완료 조건**: 작성/수정 가능, 크루장이 지원자 프로필 열람 가능.

### F3. 크루 생성/관리 (P0)
- 필드: 크루명, 대표 이미지(선택), 활동 지역(시/구), 정기 요일+시간, 페이스 밴드(예: 6'00"~7'30"), 정원, 모집 상태(모집중/마감), 소개글, 오픈카톡 링크(선택 — 채팅 대체).
- 크루장 권한: 정보 수정, 모집 마감, 멤버 목록 열람, 멤버 내보내기.
- **완료 조건**: 생성한 크루가 즉시 탐색 목록에 노출.

### F4. 크루 탐색 (P0)
- 목록: 카드형 (크루명, 지역, 요일, 페이스 밴드, 정원 현황, 모집 상태).
- 필터: 지역(시/구), 요일, 페이스 밴드(내 페이스 포함 여부), 모집 상태.
- 정렬: 최신순 / **추천순(P1)** — 추천 점수 = 지역 일치(가중 3) + 페이스 밴드 포함(가중 2) + 요일 겹침(가중 1).
- 상세 페이지: 전체 정보 + 멤버 수 + 다가오는 세션 미리보기 + [가입 신청] 버튼.
- **완료 조건**: 필터 조합 동작, 빈 결과 상태 UI, 모바일 뷰 최적화.

### F5. 매칭 — 가입 신청/승인 (P0)
- 러너: 신청(선택적 한마디 메시지) → 상태 확인(대기/승인/거절) → 신청 취소.
- 크루장: 신청 목록 → 지원자 프로필 열람 → 승인/거절.
- 규칙: 중복 신청 불가, 정원 초과 시 신청 버튼 비활성, 승인 시 멤버로 등록.
- **완료 조건**: 상태 전이(대기→승인/거절)가 양쪽 화면에 정확히 반영.

### F6. 러닝 세션 일정 (P1)
- 크루장: 세션 생성 (날짜/시간, 집결 장소 텍스트, 코스 설명, 예상 거리).
- 멤버: 다가오는 세션 목록 확인, 참석/불참/미정 응답.
- 크루장: 세션별 참석자 명단 확인.
- **완료 조건**: 크루 상세와 내 대시보드("다가오는 내 러닝")에 세션 노출.

### F7. 내 대시보드 (P1)
- 내 크루 목록, 신청 현황, 다가오는 세션 요약.

### 백로그 (P2 — 6주 내 착수 금지, 아이디어 주차장)
- 크루 후기/분위기 태그, 지도 기반 탐색, 카카오 로그인, 크루 공지 게시판, 세션 리마인드 알림(이메일).

## 4. 데이터 모델 (초안)

```
users        (id, email, created_at)
profiles     (user_id FK, nickname, avatar_url, regions[], pace_sec_per_km,
              preferred_days[], preferred_times[], goal, bio)
crews        (id, owner_id FK, name, image_url, region, regular_days[],
              regular_time, pace_min_sec, pace_max_sec, capacity,
              is_recruiting, description, chat_link, created_at)
crew_members (crew_id FK, user_id FK, role[owner|member], joined_at)
applications (id, crew_id FK, user_id FK, message,
              status[pending|approved|rejected], created_at, decided_at)
sessions     (id, crew_id FK, starts_at, place, course_note,
              distance_km, created_by FK)
session_rsvps(session_id FK, user_id FK, status[going|not_going|maybe])
```

## 5. 화면 목록 (총 11개 — 이 이상 늘리지 않기)

1. 랜딩(비로그인 홈) 2. 로그인/가입 3. 프로필 온보딩 4. 크루 탐색(목록+필터)
5. 크루 상세 6. 크루 개설/수정 폼 7. 신청 관리(크루장) 8. 세션 생성 폼
9. 세션 상세(참석 응답) 10. 내 대시보드 11. 내 프로필 수정

## 6. 성공 지표 (포트폴리오용 측정)

- 시연 시나리오(가입→탐색→신청→승인→세션 응답) 무결점 완주
- Lighthouse: Performance ≥ 80, Accessibility ≥ 90
- 핵심 도메인 로직(추천 점수, 신청 상태 전이, 정원 검증) 유닛 테스트 통과
- 지인 사용성 테스트 5명: 과업 완료율 및 피드백 기록 → 케이스 스터디 반영
