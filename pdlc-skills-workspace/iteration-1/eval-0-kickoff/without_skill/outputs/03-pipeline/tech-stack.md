# ADR-001: 기술 스택 선정 — RunMate

- **상태**: ✅ 채택 (2026-07-02)
- **결정자**: 박효균
- **맥락**: 6주 · 1인 · 주 14시간. 목표는 "배포된 MVP + 포트폴리오". 인프라에 쓰는 시간을 최소화하고 도메인 기능에 시간을 몰아야 한다.

---

## 결정 요약

| 레이어 | 선택 | 근거 |
|---|---|---|
| 프레임워크 | **Next.js 15 (App Router) + TypeScript** | 프론트+API 단일 저장소. 취업 시장 수요 1순위 스택 → 포트폴리오 가치 |
| 스타일링 | **Tailwind CSS + shadcn/ui** | 디자이너 없이 일관된 UI를 최속으로. 컴포넌트 커스텀 여지도 남음 |
| 백엔드/DB | **Supabase (PostgreSQL + Auth + RLS + Storage)** | 인증·DB·파일업로드를 직접 구현하지 않음. RLS로 보안 설계 어필 가능 |
| 상태/데이터 | **TanStack Query + Server Components** | 서버 상태 캐싱 표준. 전역 상태 라이브러리는 도입하지 않음 (필요 없음) |
| 폼/검증 | **react-hook-form + zod** | 폼 많은 앱 (프로필/크루/세션). 스키마를 클라이언트·서버 공유 |
| 테스트 | **Vitest (유닛) + Playwright (E2E 스모크 1본)** | 도메인 로직만 유닛 테스트. E2E는 핵심 플로우 1본으로 제한 |
| CI/CD | **GitHub Actions + Vercel** | PR 프리뷰 배포 자동. main 머지 = 프로덕션 배포 |
| 모니터링 | **Vercel Analytics + Sentry (무료 티어)** | 에러 추적 셋업 자체가 포트폴리오 포인트 |
| 이슈 관리 | **GitHub Issues + Projects** | 저장소와 한 몸. 커밋-이슈 연결 기록이 포트폴리오 증빙 |

**월 비용: ₩0** (전부 무료 티어. Supabase 무료 티어 1주 미접속 시 일시정지 → 6주간 매주 접속하므로 무관, 종료 후엔 데모용으로 유지 관리)

## 고려한 대안

| 대안 | 기각 사유 |
|---|---|
| React Native / Flutter (네이티브 앱) | 스토어 심사+양 플랫폼 대응은 6주 내 불가. 모바일 우선 반응형 웹 + PWA 매니페스트로 "앱 같은" 경험 제공 |
| NestJS + 별도 프론트 (2-repo) | 아키텍처 어필은 되지만 1인 6주엔 오버엔지니어링. API 설계 역량은 Next.js Route Handler + ADR 문서로 충분히 보여줌 |
| Firebase | Supabase 대비 SQL/관계형 모델링을 보여주기 어려움. 필터 쿼리(지역×요일×페이스)는 RDB가 자연스러움 |
| Prisma + 자체 Postgres (Railway 등) | Auth를 따로 구현해야 함. 인증 직접 구현은 헌장의 리스크 대응 원칙 위반 |

## 결과 (Consequences)

- (+) 1주차 안에 배포 파이프라인까지 완성 가능, 이후 5주를 도메인에 집중
- (+) 스택 전체가 채용 공고 빈출 키워드 → 포트폴리오 목적 부합
- (−) Supabase 벤더 종속 → 데이터 접근 계층을 `lib/repositories/`로 격리해 완화
- (−) RLS 정책 디버깅 러닝커브 → 2주차에 정책을 단순한 규칙 3개 이내로 유지
