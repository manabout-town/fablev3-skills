## 2. README 구조 (M5에 이 목차대로 작성)

1. **히어로**: 한 줄 소개 + 라이브 URL + 데모 영상 링크 + 핵심 플로우 GIF
2. **문제**: 왜 만들었나 (크루 모집 파편화, 초보 러너 진입장벽) — 3문단 이내
3. **해결**: 핵심 기능 3가지 (조건 기반 탐색 / 프로필 매칭 신청·승인 / 세션 RSVP)
4. **기술**: 스택 다이어그램 + 아키텍처 그림 1장 + ADR 링크
5. **품질**: 테스트 전략, CI/CD 파이프라인, Lighthouse 점수 캡처
6. **배운 점**: 사용성 테스트 결과 요약 + 회고 링크
7. **실행 방법**: 로컬 셋업 (`.env.example` 기준)

## 3. 케이스 스터디 뼈대

```
① 문제 발견     — 러닝 크루 탐색 경험의 페인포인트 (본인 경험 + 커뮤니티 관찰)
② 범위 결정     — 6주 제약에서 무엇을 버렸는가 (비목표가 곧 판단력 증빙)
③ 설계          — 데이터 모델, 매칭 흐름, 추천 점수 설계와 근거
④ 트레이드오프  — ADR 요약: 웹앱 vs 네이티브, BaaS vs 자체 백엔드, 필터 vs 지도
⑤ 검증          — 지인 5명 사용성 테스트: 과업 완료율, 발견한 문제, 고친 것/안 고친 것과 이유
⑥ 결과          — 완성 플로우, 품질 지표(Lighthouse/테스트), 데모
⑦ 다음          — 실서비스로 간다면 무엇부터 할지 (P2 주차장 활용)
```
