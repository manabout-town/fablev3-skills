# RunMate (러닝 크루 매칭 앱) Project Brief

> 작성일: 2026-07-02 | 작성 주체: PDLC 파이프라인 오케스트레이터 (킥오프)
> 이 문서는 파이프라인 1~8단계 전체가 컨텍스트의 출발점으로 삼는 기준 문서다.

## 한 줄 정의

**혼자 뛰기 지루하거나 꾸준함이 무너지는 러너에게, 지역·페이스·시간대가 맞는 러닝 크루를 찾아 연결해 주는 매칭 서비스.**

## 배경과 문제의식

러닝은 진입장벽이 가장 낮은 운동이지만, 혼자 하는 러닝은 3개월 이내 이탈률이 높다. 함께 뛸 사람이 있으면 지속률이 크게 올라가지만, 기존 채널(오픈카톡, 인스타그램, 동네 커뮤니티)로 크루를 찾는 과정은 파편화되어 있다 — 내 페이스에 맞는지, 모이는 시간대가 맞는지, 분위기가 맞는지를 가입 전에 알 방법이 없어 미스매칭과 조기 이탈이 반복된다. 러너의 프로필(지역, 목표 페이스, 선호 시간대, 러닝 목적)을 구조화하고 크루의 프로필과 매칭하면 이 탐색 비용을 크게 줄일 수 있다.

## 목표

- **비즈니스 목표**: (가상 서비스 기준) 크루 탐색 → 가입 신청까지의 전환 퍼널이 동작하는 MVP 검증. 가입 신청 전환율을 핵심 지표로 삼는다.
- **사용자 목표**: 러너가 5분 안에 자기 조건(지역/페이스/시간대)에 맞는 크루를 3개 이상 발견하고 가입 신청까지 완료할 수 있다.
- **학습/포트폴리오 목표**: 기획(AS-IS/TO-BE) → 요구사항 → 명세 → 계획 → 구현 → QA → 운영 → 포트폴리오까지 8단계 산출물을 실무 수준 품질로 완성하여, PM/PO 및 풀스택 역량을 보여주는 포트폴리오로 발행한다. **이것이 이 프로젝트의 최우선 목표다.**

## 범위 밖 (Out of Scope)

이후 단계에서 범위 방어(scope defense)에 사용한다:

- 실시간 채팅 / 크루 내 커뮤니케이션 기능 (외부 오픈카톡 링크로 대체)
- GPS 러닝 기록 트래킹 (Strava 등 기존 앱의 영역 — 재발명하지 않음)
- 결제/유료 멤버십
- 네이티브 모바일 앱 (웹 반응형으로 한정)
- 자동 매칭 알고리즘 고도화 (MVP는 필터 기반 탐색 + 추천 정렬 수준)
- 크루 간 대회/이벤트 기능

## 제약 조건

- **기간**: 6주 (2026-07-02 ~ 2026-08-13). 8단계 전체를 이 안에 완료해야 하므로 3단계(명세)와 5단계(구현) 범위 통제가 핵심.
- **팀**: 1인 (기획·디자인·개발·QA 겸임). 역할 분담 없음 — 4단계 계획은 1인 캐파 기준으로 수립.
- **기술**: Next.js + Supabase (파이프라인 고정 스택).
- **도메인 규제**: 없음 (금융/의료 아님). 단, 위치 기반 개인정보(활동 지역)를 다루므로 3단계 정책서에서 개인정보 노출 범위 정책은 다뤄야 함.

## 성공 기준

측정 가능한 형태로:

1. **파이프라인 완주**: 6주 내 8단계 산출물 전부 `done` (게이트 체크리스트 통과 기준).
2. **동작하는 MVP**: 핵심 기능 3개(예정: 러너 프로필 등록, 조건 기반 크루 탐색/필터, 크루 가입 신청)가 로컬에서 시나리오 테스트를 통과.
3. **포트폴리오 발행**: 1~7단계 산출물과 의사결정 기록이 스토리로 녹아 있는 노션 포트폴리오 1건 발행.

## 부록: 킥오프 가정 기록 (Assumptions)

이 킥오프는 비대화형(non-interactive) 환경에서 수행되어, 스킬이 요구하는 사용자 인터뷰를 진행할 수 없었다. 아래 항목은 합리적 추정으로 확정한 값이며, 사용자가 다르게 원하면 이 문서와 `pipeline-state.json`을 갱신하고 하류 단계에 `stale` 처리해야 한다.

| # | 항목 | 가정한 값 | 근거 |
|---|---|---|---|
| A1 | 서비스명 | RunMate (가칭) | 사용자가 이름을 지정하지 않음. 임의 가칭 |
| A2 | 타깃 사용자 | 크루를 찾는 개인 러너(수요 측) + 크루 운영자(공급 측) 양면 | "매칭 앱"이라는 표현에서 추정 |
| A3 | 프로젝트 성격 | 포트폴리오용 사이드 프로젝트 (`side-project`) | 사용자가 "1인 사이드 프로젝트, 포트폴리오까지 완성" 명시 |
| A4 | 기간 | 6주 (2026-07-02 시작 ~ 2026-08-13) | 사용자가 "6주짜리" 명시. 시작일은 오늘로 가정 |
| A5 | 팀 구성 | 1인 | 사용자 명시 |
| A6 | 매칭 방식 | MVP는 필터 기반 탐색 + 정렬 (자동 매칭 알고리즘 아님) | 6주 1인 프로젝트 규모에 맞는 범위 추정 |
| A7 | 플랫폼 | 반응형 웹 | 고정 스택(Next.js)과 기간 제약에서 추정 |
| A8 | 핵심 기능 3개 후보 | 프로필 등록 / 크루 탐색·필터 / 가입 신청 | 4단계에서 최종 확정 예정 — 현 시점은 후보 |
| A9 | 도메인 규제 | 규제 도메인 아님 | 러닝/커뮤니티 도메인 |
| A10 | 서비스 성격 | 가상(포트폴리오용) 서비스 — 실제 런칭보다 산출물 품질 우선 | 목표가 "포트폴리오 완성" |
