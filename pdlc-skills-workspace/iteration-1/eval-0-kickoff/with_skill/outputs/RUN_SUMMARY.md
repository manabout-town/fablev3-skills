## 따른 스킬 지침

1. **참조 문서 선행 독해**: `SKILL.md`가 지시한 대로 상태 파일 생성 전 `references/conventions.md`를 읽고 디렉토리 구조, pipeline-state.json 스키마, ID 체계, project-brief 템플릿을 준수함.
2. **킥오프 워크플로우 A**: (1) 인터뷰 항목 4개(한 줄 정의 / 프로젝트 성격 / 기간·팀 / 도메인 제약) 확정 → (2) `docs/00-project-brief.md` 작성(규약 §6 템플릿 준수) → (3) `docs/pipeline-state.json` 초기화(규약 §2 스키마, 모든 단계 pending, current_stage: 1) → (4) 1단계 시작 여부 질문(아래 참조).
3. **언어 규칙**: 한국어 본문 + 업계 용어 첫 등장 시 영어 병기(scope defense, exit criteria 등).
4. **상태 파일 단일 진실 공급원 원칙**: 상태 변경은 스킬 워크플로우 내에서만 수행, 사용자에게 수동 수정 요구하지 않음.
5. **한 세션에 파이프라인 전체를 끝내지 않기**: 킥오프까지만 수행하고 1단계 산출물은 만들지 않음 (사용자 요청 범위도 "킥오프 + 세팅").
6. **decisions/risks 기록**: 킥오프 시점의 범위 결정과 가정을 `decisions` 배열에, 6주 완주·가정 불일치·요구 팽창 리스크를 `risks` 배열에 기록.

## 따를 수 없었던 / 조정한 지침

1. **대화형 인터뷰 불가**: 스킬은 "한 번에 몰아 묻지 말고 대화로 풀어라"라고 지시하지만, 본 실행은 비대화형이라 인터뷰를 진행할 수 없었음. → 사용자 메시지에서 확정 가능한 값(6주, 1인, 사이드 프로젝트, 포트폴리오 목표)은 그대로 반영하고, 나머지(서비스명, 타깃 세그먼트, 매칭 방식, 플랫폼 등)는 합리적 가정으로 확정한 뒤 **가정 10건을 `00-project-brief.md` 부록 표에 명시 기록**함. 가정 불일치 위험은 RISK-002로 등재.
2. **"1단계를 시작할지 물어본다" (워크플로우 A-4)**: 비대화형이므로 실제 질문/응답이 불가능. → 질문을 여기 기록하는 것으로 갈음: **다음 단계는 1단계 `pdlc-1-asis-tobe`(AS-IS/TO-BE 프로세스 분석)이며, 시작 시 `docs/00-project-brief.md`를 입력으로 사용한다. 진행할까요?** 사용자 확인 전이므로 1단계 status는 `pending`으로 유지함.
