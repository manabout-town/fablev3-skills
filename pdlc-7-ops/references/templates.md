## docs/07-ops/redeploy-plan.md

```markdown
# [서비스명] 재배포 계획

> 대상: 개선 계획 "다음 스프린트" 항목 반영 배포 (버전 vX.Y)

## 1. 배포 전 체크리스트
- [ ] 마이그레이션 하위 호환 확인 (기존 코드가 새 스키마에서 동작하는가)
- [ ] `npm run build` 통과
- [ ] 회귀 TC 실행: TS-### (P1 경로 전체)
- [ ] 환경변수 변경 사항 반영 확인
- [ ] 롤백 절차 리허설 (아래 4절)

## 2. 배포 절차
| 순서 | 작업 | 도구 | 검증 |
|---|---|---|---|
| 1 | DB 마이그레이션 적용 | supabase db push / migration up | 스키마 확인 쿼리 |
| 2 | 앱 배포 | Vercel (또는 대상 환경) | 빌드 성공 |
| 3 | 스모크 테스트 | 아래 3절 | 전부 Pass |

(원칙: 하위 호환 마이그레이션 전제 하에 DB 먼저 → 코드 나중. 비호환 변경은 expand-migrate-contract 3단계로 쪼갠다)

## 3. 배포 후 스모크 테스트
| # | 확인 | 기대 |
|---|---|---|
| 1 | 로그인 → 핵심 여정 1회 완주 | 오류 없음 |

## 4. 롤백 계획
- **발동 기준 (수치로)**: 예) 배포 후 30분 내 오류율 5% 초과, 핵심 여정 스모크 실패, Critical 버그 신고 접수
- **판단자**: (1인 프로젝트면 본인, 기준 충족 시 즉시)
- **절차**:
  1. 앱: Vercel 이전 배포로 instant rollback
  2. DB: 마이그레이션 롤백 가능 여부 — 가능 시 down 스크립트, 불가 시 (데이터 보존 대안: 신규 컬럼 방치 + 코드만 롤백)
- **롤백 후**: 원인 분석 → OPS 이슈로 기록 → 재시도 조건 정의
```
