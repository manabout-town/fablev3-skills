## docs/02-requirements/brd.md

```markdown
# [서비스명] 요구사항 정의서 (BRD)

| 문서 버전 | 작성일 | 승인자 | 상태 |
|---|---|---|---|

## 1. 배경과 목적
(project-brief, 1단계 분석 요약 3~5문장)

## 2. 성공 지표 (KPI)
| 지표 | 정의 | 목표값 | 측정 방법 |
|---|---|---|---|

## 3. 사용자 요구사항 (기능 요구, FR)

| ID | 요구사항 | 상세 | 근거 | 우선순위 | 비고 |
|---|---|---|---|---|---|
| REQ-001 | 사용자는 ~할 수 있다 | | PP-001, INS-002 | Must | |

(요구사항은 "사용자는 ~할 수 있다" 형태로. 구현 방법 지정 금지 — "버튼을 누르면" ❌)

## 4. 비기능 요구사항 (NFR)

| ID | 분류 | 요구사항 | 근거 | 우선순위 |
|---|---|---|---|---|
| REQ-101 | 성능 | 주요 화면 로딩 3초 이내 | | Should |

(분류: 성능 / 보안 / 가용성 / 접근성 / 법규 준수)

## 5. 하지 않을 것 (Won't — Out of Scope)
| 항목 | 사유 | 재검토 시점 |
|---|---|---|

## 6. 가정과 의존성
- 가정(Assumption):
- 의존성(Dependency):

## 7. 오픈 이슈
(결정되지 않은 것 — 3단계 전 해소 필요 항목 표시)
```

## ID 규칙

- FR은 REQ-001부터, NFR은 REQ-101부터 시작해 번호대로 구분한다.
- 근거 컬럼에는 PP-###(1단계) 또는 INS-###(인터뷰)만 허용. 근거가 "상식"이면 사용자에게 확인받고 "이해관계자 요청"으로 기록.
